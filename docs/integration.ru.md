# Добавить обновляемый список заказов в приложение

[← README](../README.md) · [Версии](index.md) · [English](integration.en.md)

## 1. Выбрать подходящий объект

`SseFeed` — готовый React-список: один аккаунт/поток, одно соединение, данные в памяти и соответствующий им checkpoint. Сообщения заменяют строки по бизнес-ключу. Состояние соединения, пауза, подключение и восстановление снимка уже встроены.

Подходит для последних изменений заказов, уведомлений и небольших обновляемых списков. Не заменяет полный архив событий, редактируемую таблицу и обработчик произвольных команд удаления. Если у приложения уже есть собственное хранилище данных или другая модель событий, используйте `SseRelayProvider` + `useSseRelay`. Этот уровень показан в [руководстве provider](v0.1.0/guide.ru.md).

## 2. Подключить к существующему проекту

Возьмите зависимости и первый компонент из [Get started](../README.md). Дополнительно устанавливать CSS не нужно: есть нейтральная разметка, обычные кнопки и доступный статус соединения. Цвет текста наследуется от приложения; можно передать свои классы и стили.

```text
src/
  auth/session.ts                    существующая авторизация
  orders/OrderNotifications.tsx       копия полного модуля интеграции
  pages/OrdersPage.tsx                место OrderNotifications на странице
server/
  GET /api/events                    авторизованный поток протокола relay
  GET /api/snapshot                  согласованные данные аккаунта и курсор
```

[Полный модуль](../examples/orders/OrderNotifications.tsx) получает `OrderSession` из вашей OAuth-интеграции, сохраняет стабильный DPoP transport, проверяет бизнес-поля и подключает оба маршрута. Писать reducer списка, эффекты переподключения и сохранение курсора пользователю не требуется.

Чтобы попробовать локально, [запустите пример](../CONTRIBUTING.md) и откройте `/feed.html`. Его [экран](../examples/notifications/feed-main.tsx) использует тот же компонент; [сервер](../examples/notifications/server.mjs) — настоящий relay и проверки DPoP. Выбор аккаунта и выдача токена в нём синтетические, это не рабочая OAuth-авторизация.

<a id="business-fields"></a>
## 3. Описать только бизнес-данные

Сообщение примера — `{ key, text }`: ключ определяет уведомление о заказе, текст содержит его актуальное состояние.

- `decode(value)` проверяет неизвестное JSON-значение и возвращает типизированный объект. Исключение отклоняет событие без продвижения курсора.
- `getKey(item)` возвращает непустой стабильный бизнес-ключ. Повторный ключ заменяет строку, поэтому повтор событий не создаёт дубликаты строк.
- `renderItem(item)` задаёт содержимое строки. Возвращайте обычный React-текст или элементы; feed сам не вставляет HTML.

Эти функции описывают предметную область. Обновление списка, конечные повторы, остановка соединения и порядок checkpoint находятся в библиотеке. Изменение существующего ключа сохраняет позицию строки; новый ключ добавляется в конец. Для удаления, сортировки или транзакционных действий подходит уровень provider.

<a id="snapshot"></a>
## 4. Восстановиться после удаления старых событий

Пока браузер был отключён, сервер мог удалить старую историю. Тогда feed показывает необходимость снимка. `snapshotUrl="/api/snapshot"` включает встроенное восстановление с теми же авторизованным fetch, заголовками и credentials. Для готового SDK приложения вместо URL передайте `loadSnapshot`. Оба варианта одновременно — ошибка настройки:

1. Компонент останавливает прежнее соединение и ждёт его завершения.
2. Запрашивает URL снимка либо вызывает ваш загрузчик с `{scope,signal}`.
3. Проверяет область и курсор, декодирует все записи до изменения списка.
4. Синхронно устанавливает список, затем продолжает с соответствующего курсора.

Ответ сервера:

```json
{
  "scope": { "accountId": "verified-account", "streamId": "notifications" },
  "cursor": "opaque-server-position",
  "items": [{ "key": "order-42", "text": "Заказ 42 отправлен" }]
}
```

Данные и курсор должны соответствовать одному согласованному снимку сервера. Аккаунт определяется проверенной авторизацией; строка выше показывает форму ответа, а не механизм выдачи прав. Компонент проверяет форму и область, но не может доказать атомарность произвольной серверной реализации.

Ошибка загрузки или чужая область оставляет прежний список и позволяет повторить восстановление. Удаление компонента/смена аккаунта отменяет загрузчик; поздний ответ не попадает в новый аккаунт. Без загрузчика остаётся явное сообщение о необходимости снимка: отсутствующие события не пропускаются молча.

<a id="limits"></a>
## 5. Согласовать жизнь списка и соединения

`FeedDefaults.MAX_ITEMS` равен 100. Меняйте `maxItems`, если продукту нужно другое окно отображения. При заполнении из списка уходят самые старые добавленные ключи; серверные события не удаляются. Для HTTP-снимка есть отдельный предел `snapshotMaxBytes`: по умолчанию `FeedDefaults.SNAPSHOT_MAX_BYTES` (1 MiB). До разбора JSON проверяются Content-Length и фактически полученные байты. Превышение отменяет чтение, прежние данные и курсор не меняются.

`snapshotTimeoutMs` по умолчанию равен `FeedDefaults.SNAPSHOT_TIMEOUT_MS` (10 секунд) и ограничивает всё восстановление. По истечении срока HTTP-запрос и чтение body отменяются; прежний список сохраняется, кнопка восстановления снова доступна. Тот же срок отменяет сигнал пользовательского `loadSnapshot`: загрузчик, получение токена и callback заголовков должны учитывать отмену и завершать promises. При собственном SDK лимит памяти ответа/объекта задаёт загрузчик: HTTP-ограничение не может проверить уже созданные SDK данные.

Feed самостоятельно хранит список и checkpoint в памяти. Внешний постоянный checkpoint не принимается, потому что сам список недолговечный. Смена аккаунта, потока или `maxItems` заменяет их вместе. После reload нужны replay либо снимок. Возврат к прежнему аккаунту не воскрешает его старый список.

Пауза прекращает получение, сохраняя экран. Подключение — явное действие пользователя с новым конечным бюджетом попыток. Автоматические повторы сетевых ошибок также ограничены. Смена области/удаление компонента останавливает прежнее соединение. React Activity может сохранять данные и checkpoint при очистке эффектов; сама библиотека не требует API только из React 19.

<a id="component-api"></a>
## 6. Настроить внешний вид и подключение

| Prop | Назначение / значение по умолчанию |
|---|---|
| `scope` | Авторизованные `{accountId,streamId}` или `null` для отключённого экрана. |
| `url` | Endpoint relay: строка либо URL callback базовой библиотеки. |
| `decode`, `getKey`, `renderItem` | Обязательные бизнес-форма, идентификатор и вид строки. |
| `transport` | Стабильные настройки транспорта: авторизованный fetch, refresh, повторы/профиль. |
| `snapshotUrl` | JSON endpoint снимка; тот же авторизованный GET transport, headers и credentials, отмена и запрет redirects. |
| `snapshotMaxBytes` | Положительное безопасное целое; предел HTTP body до разбора JSON. По умолчанию `FeedDefaults.SNAPSHOT_MAX_BYTES` (1 MiB). |
| `snapshotTimeoutMs` | Положительный таймер до 2147483647 мс. По умолчанию `FeedDefaults.SNAPSHOT_TIMEOUT_MS` (10 с). Всё восстановление, включая SDK, учитывающий отмену. |
| `loadSnapshot` | Альтернативный загрузчик SDK вместо snapshotUrl; получает scope/signal. |
| `maxItems` | Положительное целое; по умолчанию `FeedDefaults.MAX_ITEMS`. Изменение сбрасывает сессию/список. |
| `locale` | `en` или `ru`, по умолчанию `en`. Переводятся встроенные кнопки и статусы; бизнес-текст задаёте вы. |
| `title` | Заголовок и доступное имя секции. По умолчанию Notifications / Уведомления. |
| `className`, `style` | Стили приложения; содержимое строки задаёт `renderItem`. |

У статуса одна спокойная live region; кнопки стандартные, доступны с клавиатуры и заблокированы, когда действие недоступно. Ошибка снимка объявляется через alert. У анимации есть [статичный вариант](assets/feed.png); компонент не навязывает декоративное движение.

## 7. Использовать существующую авторизацию

Передавайте стабильный transport. Для DPoP [полный модуль](../examples/orders/OrderNotifications.tsx) создаёт `createDpopFetch` с ключом, с которым получен access token. OAuth SDK предоставляет актуальный токен и необязательный refresh. Адаптер подписывает каждый GET/reconnect и обрабатывает nonce challenge, но не выполняет вход. [Настройка DPoP](https://github.com/dlorian59/browser-sse-relay/blob/main/docs/dpop.ru.md).

Node fixture закрывает поток по истечении токена и проверяет подпись proof, привязку и повторы. Его журнал в памяти и свободный выбор аккаунта нужны для воспроизведения. Рабочему relay необходимы настоящая авторизация и хранение истории.

## Типичные ошибки

- **Новый transport на каждом рендере:** сохраните его через memoization, чтобы обычное обновление страницы не перезапускало соединение.
- **Пустой или изменяемый ключ:** строку нельзя безопасно заменить. Нужен стабильный бизнес-ID, а не индекс массива.
- **Снимок из несогласованных чтений:** список и курсор могут расходиться. Сервер должен получать их согласованно.
- **100 строк экрана приняты за все данные:** это окно отображения. Полные отчёты получайте из бизнес-API.
- **Постоянный курсор при пустом списке:** SseFeed избегает этого, храня обе части вместе. Для долговечного состояния используйте provider с явной схемой сохранения.
